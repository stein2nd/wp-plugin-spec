# wp-plugin-spec - REST API および外部サービス連携 (ひな型)

* 各プラグインリポジトリ直下の `docs/` フォルダー等にコピーして利用することを想定する。
* コピー後、1行目を `# <plugin-slug> - REST API および外部サービス連携` に変更すること。
* ファイル名の一例: `docs/SPEC_API_AND_INTEGRATION.md`

* **目的**: REST エンドポイントと外部サービス連携を、プラグイン固有の設計に具体化する。
* **内容例**:
  * `/plugin-slug/v1/...` ごとの
    * メソッド (GET/POST/PUT/DELETE)
    * パラメータ (型・必須／任意)
    * レスポンス JSON スキーマ
    * 認可ポリシー・`permission_callback` 条件
    * エラーの HTTP ステータスとエラーコード
  * 外部 API (例: OpenAI, DeepL 等) の呼び出し仕様
* **AI 的メリット**:
  * 「このエンドポイントの PHP 実装を作って」「このレスポンスを使うフロントのフックを書いて」といったタスクを、**1エンドポイント単位で安全に委譲できる**。

REST クラスは、アダプタです。サニタイズ、権限、`WP_Error` / HTTP への変換、`wp_remote_*` / Options / `$wpdb` は、ここに閉じます。判断・バリデーションは、`includes/domain/` の純関数へ委譲します。巨大なサービスオブジェクトは、使いません。

## 1. REST API 仕様

* すべての REST エンドポイントは、`/plugin-slug/v1/...` を基本とする。
* `permission_callback` で権限チェックを必ず行う。
* Nonce チェックを必須とする。
* エラー系レスポンスには、HTTP ステータスとエラーコードを書く。`WP_Error` を握りつぶさない。

## 2. 外部 API、サービス連携 (該当する場合)

* 外部 API (例: DeepL) を利用する場合は、`wp_remote_post` / `wp_remote_get` をアダプタで呼び、エラーハンドリングを実装する。
* リクエストの組み立てや応答の解釈のうち、判断にあたる部分は純関数に出す。
* API キーはアダプタから注入する。ライブラリ内部やドメイン関数に埋め込まない。
* テーマ / 他プラグイン連携は Composer 依存より先に、存在チェックとフックで行う。

## 3. AI 伴走開発での使い方メモ

* **API 実装タスク**:
  * 本ファイルの「1.2. 各エンドポイント詳細」の対象エンドポイント節を指定し、`includes/RestController.php` (アダプタ) と `includes/domain/` の純関数を依頼する。
  * REST コントローラにビジネス判断と永続化を兼ねさせないこと。
* **外部連携タスク**:
  * 「2. 外部 API、サービス連携」の該当サービスを指定し、`wp_remote_post` / `wp_remote_get` をアダプタに閉じた実装を依頼する。
* 参照させる関連仕様:
  * `SPEC_ARCHITECTURE.md` (アダプタとドメインの境界)
  * `SPEC_DATA_DICTIONARY.md` (保存先・読み書きするデータ)
