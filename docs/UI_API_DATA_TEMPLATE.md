# wp-plugin-spec - 画面、API、データ (統合ひな型)

* 各プラグインリポジトリ直下の `docs/` フォルダー等にコピーして利用することを想定する。
* コピー後、1行目を `# <plugin-slug> - 画面、API、データ` に変更すること。
* ファイル名の一例: `docs/SPEC_UI_API_DATA.md`

* 小〜中規模プラグイン向けに、「画面仕様、API 仕様、データ仕様」を1ファイルにまとめておき、大きくなったら分割版を使う。

**分割版 (同一 `docs/` 内):**
* `SPEC_UI_AND_FLOWS.md` — 管理画面、フロント UI と画面遷移
* `SPEC_API_AND_INTEGRATION.md` — REST API および外部サービス連携
* `SPEC_DATA_DICTIONARY.md` — データ、設定値、ストレージ定義

React / REST / Settings は、アダプタです。判断は、純関数です。永続化と `wp_remote_*` は、アダプタに閉じます。詳細な設計方針は、`docs/SPECS.md` の「2. 設計方針」、置き場所は、`SPEC_ARCHITECTURE.md` です。

## 1. 画面仕様 (UI) とフロー

* 設定ページは `add_options_page` または `add_menu_page` を使う (PHP アダプタ)。
* 読み書きは `register_setting` / `get_option` / `update_option` をアダプタで行う。
* `sanitize_callback`、Nonce、capability は必須。
* バリデーションと判断は純関数へ出す。コンポーネントに混ぜない。
* 余白・テキストサイズは `rem` を基本とする。詳細は `SPECS.md` のスタイル規約。

* `permission_callback` と Nonce は必須。
* エラー系は HTTP ステータスとエラーコードを書く。`WP_Error` を握りつぶさない。
